# История: v1 → v2

## v1 (весна 2026)

Постановка «прогноз оттока», выбор CatBoost по PR-AUC на 5-fold CV, порог по максимуму F1 на
OOF, одна оценка на test. Итог v1 (файлы сохранены в `docs/v1/`):

| Модель | CV PR-AUC | Порог | Test ROC-AUC | Test PR-AUC | Test F1 |
|---|---|---|---|---|---|
| CatBoost (depth 4, lr 0.03, l2 10, 500 итераций) | 0.6738 ± 0.0236 | 0.35 (F1) | 0.8447 | 0.6661 | 0.6300 |

Что было не так:

- постановка: «прогноз» на снимке, где признаки и метка сняты одновременно;
- метрика и порог не отвечали на бизнес-вопрос (F1 считает цены FP и FN равными);
- один 5-fold и сравнение средних без проверки значимости; параметры CatBoost на краю сетки
  и зашитые 500 итераций;
- val-выборка почти не использовалась и путала;
- SHAP считался на данных, на которых модель обучалась;
- тесты требовали скачанный датасет: на чистом клоне проходили 6 из 48.

## v2

| Что | Как стало |
|---|---|
| Постановка | ранжирование по снимку под бюджет удержания; README, «Что модель делает и чего не делает» |
| Метрики | lift и precision/recall на верхних 10%/20%, cumulative gains; PR-AUC вторичная |
| Сегменты | метрики внутри каждого типа контракта на OOF с bootstrap-CI |
| Калибровка | reliability-кривая, Brier, intercept/slope; калибратор только внутри CV и только при значимом улучшении |
| Порог | по ожидаемой прибыли с явными допущениями и анализом чувствительности |
| Выбор модели | RepeatedStratifiedKFold 5×5, corrected t-test, правило «незначимо → LogReg» |
| CatBoost | early stopping внутри каждого фолда, сетка depth 2–4, lr 0.01–0.03, l2 3–30 |
| LogReg | сплайн по `tenure`, расширенная сетка C |
| Признаки | 6 кандидатов + 2 удаления с абляцией и VIF |
| Test | только `train.py --evaluate-test`, журнал `results/test_access_log.json` |
| Тесты | синтетический набор, smoke-тест полного `train.py`, CI ubuntu + windows, ruff |

## Test — второй взгляд

Test-выборка v2 та же, что в v1: новое разбиение train/test повторяет первый
`train_test_split` v1 с тем же seed, бывшая val вошла в train. Метрики v1 на test видели до
начала доработки, поэтому оценка v2 на test — второй взгляд и может быть немного
оптимистичной. Все решения v2 приняты на CV внутри train, test открыт один раз в конце.
